# SNU InternWatch

서울대 경력개발센터 인턴 게시판의 새 공고를 **내 기준으로** 골라 주는 도구.
수집 북마크가 공고를 파일로 모으고, ChatGPT Edu 공유 GPT가 그 파일을 읽어 추천·참고·직접 확인·제외로 나눈다.

- 북마크 설치: https://sinabro-2004.github.io/snu-internwatch/
- InternWatch GPT: https://chatgpt.com/g/g-6adf300a445481c2ad2a1cab74cb40d1-snu-internwatch (서울대 ChatGPT Edu 계정으로 열림)

## 쓰는 법

1. **북마크 설치** — 설치 페이지의 버튼을 북마크바로 끌어다 놓는다.
2. **수집** — 경력개발센터(career.snu.ac.kr)에 로그인한 탭에서 북마크를 누른다.
   새 공고를 모아 `인턴공고_날짜_1ofN.md`(20건씩)와, 본문이 이미지뿐인 공고가 있으면 `포스터_날짜.pdf`를 만든다. 화면의 "받기"로 내려받는다.
3. **판정** — InternWatch GPT에 파일을 올리고 "판정해줘"라고 보낸다.
   처음이면 "기준 만들기"로 시작한다. GPT가 질문 7개로 기준 파일(`인턴 필터 기준.md`)을 만들어 주고, 다음부터는 이 파일을 공고 파일과 함께 올린다.

한 번 모은 공고는 다음 실행 때 건너뛴다. 상세 페이지를 못 받은 공고는 건너뛰지 않고 다음 실행 때 다시 받는다.
처음부터 다시 모으려면 패널의 "본 공고 기록 지우기"를 두 번 누른다. 패널을 닫았어도 다음 실행 때 지난번 파일과 포스터 PDF를 다시 받을 수 있다.

## 기준 인터뷰가 묻는 것

원하는 분야·직무 · 빼고 싶은 직무 · 근무지 · 학적 · 근무 시기 · 선호 회사 · 점수 기준.
점수는 실제 업무로만 매기고, 선호 회사가 있으면 같은 점수 안에서 앞에 놓는다.

학적은 졸업예정자·기졸업자·석사만 받는 공고를 어떻게 할지 고른다.

| 선택 | 동작 |
|---|---|
| 빼기 | 제외한다. 단 "휴학생 가능"처럼 재학생도 받는 단서가 있으면 직접 확인 구획에 업무 점수와 함께 둔다 |
| 표시만 | 직무로만 판정하고 추천 표의 자격 칸에 `⚠ 졸업예정자·기졸업자`처럼 표시한다 |

## 판정이 맞는지 확인한 방법

2026-10-26에 모은 공고 40건에 개발자 본인이 관심·애매·없음 라벨을 붙이고(GPT 판정을 보기 전에, 직무만 보고) GPT 판정과 비교했다.
라벨·판정·집계 스크립트와 실행 조건은 [`eval/`](eval/)에 있다. v0.1.2 지침 결과(v0.1.3에서 바뀐 잘린 본문·이미지 규칙은 이 40건 중
잘린 두 공고의 판정을 바꾸지 않는다 — 하나는 근무지로 제외, 하나는 이미 `확인 필요(본문 잘림)` 추천이었다. 다시 돌리지는 않았다):

| 학적 설정 | 관심 17건 중 추천 | 직접 확인 | 놓침 | 관심 없는데 추천 |
|---|---|---|---|---|
| 빼기 | 7 | 3 | 7 | 0 |
| 표시만 | 13 | 3 | 1 | 1 |

- **빼기의 놓침 7건** — 5건은 지원 자격이 졸업예정자·기졸업자·석사로 한정된 공고라 기준대로 뺀 것이다(KB증권 RA·포스코경영연구원 RA·KKR·그리니치PE·엔라이튼).
  나머지 2건은 직무 판단이다. 미즈호은행은 "영업부서 서포트"라서 영업 직무로 뺐고, ANUA 전략 리서치 RA는 "마케팅 전략 수립을 위한 리서치"를 마케팅으로 봤다.
- **같은 공고를 실행마다 다르게 보기도 한다.** ANUA는 표시만 실행과 그 전 실행들에서는 "전략 리서치"로 보고 추천 5점을 줬다. 경계에 걸친 직무는 GPT 판정이 흔들린다.
- **표시만의 오탐 1건**(엔라이튼 사업개발)은 GPT가 "발전소 가치평가, 투자 검토 보고서 작성 지원"을 근거로 4점을 줬다. 라벨은 "없음"이었다.
- GPT가 공고를 빠뜨리지 않게, 파일 머리의 id 수와 판정한 id 수를 맞춰 보는 검사 줄을 답 끝에 반드시 쓴다. 지금까지 모든 실행에서 일치했다(81건 한 번에 판정한 시험 포함).
- 본문이 이미지뿐인 포스터형 공고는 전체의 약 26%였다. 같은 40건에서 포스터 PDF를 함께 올리자 직접 확인이 19건에서 7건으로 줄었다.
- 이 40건을 보면서 지침을 고쳤으므로, 처음 보는 공고에서는 숫자가 이보다 나쁠 수 있다. 라벨도 한 사람의 판단이다.

경계 사례(공고 안 지시문, 잘린 본문, 휴학생 단서, 석사 한정, 포스터 판독, 포스터 일부 누락)는 [`examples/`](examples/)의 합성 공고 9건으로 따로 확인했다.

## 개인정보

- 스크립트는 내 브라우저 안에서 돈다. 공고 내용·기준 파일을 별도 서버로 보내는 코드는 없다.
- 외부로 나가는 요청은 셋이다. 스크립트 파일을 받는 jsDelivr, 경력개발센터 페이지(로그인 쿠키 사용), 공고에 실린 포스터 이미지 주소(다른 사이트면 쿠키 없이). 이 요청들에서 접속 IP 같은 일반 접속 정보는 각 서버에 남는다.
- 이미 본 공고 id와 마지막으로 만든 파일은 그 브라우저의 경력개발센터 사이트 저장소(localStorage)에 남는다. 계정이 아니라 브라우저 단위다.
- 북마크는 태그로 고정한 버전을 SRI 해시로 검증한 뒤에만 실행한다. CDN의 파일이 바뀌면 실행되지 않는다.
- 파일을 GPT에 올리는 건 사용자가 직접 한다. 기준 파일에는 이름·학번을 적지 않는다.

## 한계

- 경력개발센터 페이지 구조가 바뀌면 수집이 깨진다. 목록에서 공고 링크보다 적게 읽거나 상세 표가 없으면 "공고 없음"으로 넘기지 않고 오류·재시도로 알린다.
- 한 번에 최근 10쪽(약 100건)까지만 본다. 그보다 오래된 공고가 남았으면 패널이 알려 준다.
- 본문은 공고당 5,000자까지 넣는다. 자르면 잘린 뒷부분에서 자격·조건 줄을 바로 뒤 2줄(예외 문장)과 함께 옮긴다. 옮긴 줄은 원문 일부라서,
  GPT는 잘린 공고를 학적 때문에 제외하지 않고 직접 확인으로 둔다(근무지·직무 제외는 그대로).
- 포스터는 본문 텍스트가 300자 미만인 공고만, 공고당 3장까지 받는다. 일부만 받으면 공고 파일에 "이미지 N장 중 M장만"이라고 적고, GPT는 텍스트에서 자격을 못 찾으면 `확인 필요(이미지)`로 표시한다.
- GPT 판정은 틀릴 수 있다. 지원 전에 공고 원문을 확인한다.
- 판정은 ChatGPT Edu(서울대 계정) 공유 GPT로 한다. ChatGPT 화면 공지에 따르면 GPT는 2026-12-11까지 플러그인으로 옮겨야 그 뒤에도 쓸 수 있다 — 옮기면 이 링크를 바꾼다.

## 파일

| 경로 | 내용 |
|---|---|
| `collect.js` | 수집 스크립트. 북마크가 jsDelivr에서 태그 고정 버전을 불러온다 |
| `index.html` | 북마크 설치 페이지(GitHub Pages) |
| `gpt/instructions.md` | 공유 GPT 지침 전문 |
| `gpt/기준 템플릿.md` | GPT 지식 파일 — 기준 파일 예시 |
| `tests/` | 수집·파서·파일 생성 테스트 32개 |
| `examples/` | 로그인 없이 시험해 볼 합성 공고 9건·포스터 PDF와 GPT 판정 예시 |
| `eval/` | 판정 검증 자료 — 정답 라벨, GPT 판정, 집계 스크립트 |

## 개발

```
node --test tests/collect.test.js
```

- 파서는 개인용 Python판 InternWatch(비공개)를 옮긴 것이다. `tests/golden.json`은 같은 HTML을 Python판으로 파싱한 결과이고, JS 파서가 이것과 같은지 본다. `make_golden.py`는 Python판이 있어야 돈다.
- `tests/fixtures/`의 목록·상세 HTML은 실제 페이지 사본이다. 이름·학번·보안 토큰은 지웠다. `detail_poster.html`과 `tile_*.jpg`는 합성 픽스처다.

코드와 GPT 지침은 Claude(Anthropic)로 작성했다. 공고 판정은 ChatGPT Edu 공유 GPT가 한다.
